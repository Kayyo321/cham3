## Objective

Deliver the approved right-hand Plasma 6 panel on Debian 13/KWin Wayland, with three isolated execution aliases, five tags per alias, verified contract tools, network configuration and global isolation controls, and two scoped task sections. Demonstrate actual backend behavior and trustworthy status without granting authority through desktop navigation.

This is a roadmap implementation task, not a report of implemented behavior. M5 is the KDE milestone in `docs/engineering/ROADMAP.md`; M4 remains network enforcement. M1 supplies desktop/image foundations; M4 and applicable M6 gates supply verified networking and live-policy reliability.

## Acceptance criteria

- [ ] **AC-01 — Layout/package:** A clean Debian 13 x86-64 test installation boots to Plasma 6 Wayland with the right-edge 56–64 logical-px panel and exact ADR order; both 2×2 placement and full-width protocol bar match. Tray and vertical clock/calendar remain at the bottom. Record scaling, supported outputs/heights, overflow, keyboard access, non-color status, and reduced-motion behavior. Package upgrade preserves user customization and cannot reactivate stale security state.
- [ ] **AC-02 — User launcher:** Authenticated user's circular avatar opens the specified search/category flyout with verified contract badges and public `key_id`; Lock, Log Out, Reboot, Power Off work through authenticated session controls. Keys/secrets never appear in the flyout or logs; missing identity/status is explicit.
- [ ] **AC-03 — Aliases/HUD:** Rose/Purple/White segments select Direct/Tor/Offline aliases immediately. `Super + Tab`, repeated `Tab`, modifier release and `Escape` obey commit/cancel semantics. HUD shows live previews of the three same-user aliases without leaking buffers to applications, other users, or locked sessions. App/browser data profiles are isolated, including helpers, and selection cannot change running network policy or grant Direct to an unauthorized launch.
- [ ] **AC-04 — Tags:** Tags `1`–`5` are independently scoped to each alias, giving 15 contexts. Empty/occupied/active/urgent indicators match observed windows. Left-click changes view; pager `Super + Click` moves the active window within its alias while preserving sandbox/profile/contract/mode. Resolve simultaneous active/urgent states and stale-window races visibly.
- [ ] **AC-05 — Contract grid:** Grid buttons open the standalone Contract Handler, read-only ECR Explorer when its dependency is approved/available (otherwise clearly unavailable), and Active Contracts Monitor. Monitor binds live processes to verified sandboxes and shows accurate revocation outcome/limits. Hot view latches, uses a reticle, highlights on hover, opens the verified inspector once and disarms; `Escape`, destroyed target, lock/session loss and attribution failure clear it safely.
- [ ] **AC-06 — Inspection/input:** Application-surface `Super + Click`, keyboard-only shortcut and taskbar/context-menu actions inspect the correct verified runtime without signing. Pager/task-icon modifier clicks take only their intended action. Synthetic application input, spoofed titles/IDs, rapid focus changes and ID reuse cannot inspect/authorize the wrong sandbox or cause a second action.
- [ ] **AC-07 — Protocol editor:** All three tabs expose the ADR settings. Validate Direct resolver/gateway/interface/fallback inputs; Tor daemon/bridge/transport/guard/exit/circuit/SOCKS inputs; Offline loopback/peripheral/Unix-socket policy inputs against approved schemas and mandatory restrictions. Exact user-approved proposals are cryptographically authorized through the restricted vault workflow before backend writes. Reject unsafe listeners, raw configuration/command injection, proxy bypasses and Tor-to-Direct fallback. Cancel, stale approval, partial update and failed enforcement cannot increase authority or display proposed state as active.
- [ ] **AC-08 — Full Isolation Kill:** Off denies WAN/LAN and IP loopback, including IPv4/IPv6 TCP/UDP, existing flows and alternative IP traffic, across host/namespaces/wired/radio/peripheral paths. nftables/namespace controls and supported rfkill controls enforce the overlay. Authorized `AF_UNIX` Wayland/KWin/D-Bus/control IPC works; unauthorized sockets and IPC network proxies remain denied. Denial still works with locked/unavailable vault and unavailable ECR. Restore is separately authenticated, keeps current contract restrictions, and cannot grant Direct, revive revoked/expired grants, or bypass Tor. Boot, reload, crash, new interface/namespace and suspend/resume remain fail closed; pending/unknown/failure cannot report isolated success.
- [ ] **AC-09 — Settings/tray:** Gear opens KDE System Settings with cham3 security sections prominent. Notifications, volume, battery and trusted Tor circuit status remain functional; kill/pending/failure state is distinguished from circuit metadata.
- [ ] **AC-10 — Tasks:** Section A contains only verified active-alias/current-tag tasks with backend-confirmed network pips. Divider precedes Section B, containing other tags in that alias at 70% opacity with solid circular numbered badges. Left-click jumps/focuses; `Super + Click` pulls without changing view or authority. Other aliases/users are excluded, and unknown attribution/status has a diagnostic presentation rather than a fabricated compliant badge.
- [ ] **AC-11 — State/authorization:** Display requested, signed/verified, pending, enforced, failed/unknown, and restart-required states distinctly. Reject stale confirmation after service restart, revision change, ID reuse or session change. Effective policy remains the intersection of mandatory policy and currently valid grants. Backend outage cannot leave optimistic badges or authorize a change.
- [ ] **AC-12 — Delivery gates:** Record exact base/target commits, versions, commands, PASS/FAIL/NOT_RUN/BLOCKED, artifacts and limitations. Independent architecture/security review and independent verification cover exact implementation commits and test sensitivity. Update task/status with evidence and deliver the structured handoff before completion; no required gate is waived by documentation checks or mocks.

## Security considerations

- **Boundaries:** Plasmoids/editor/utility UIs submit bounded requests; trusted services resolve identity, policy, authorization, signing and enforcement separately. Apps are untrusted and cannot directly access signing keys, privileged networking or ECR stores.
- **Threats:** Window/title/ID spoofing, same-user profile access, helper escapes, synthesized input, stale status/approval, configuration injection, IPC proxying, unintended listener exposure, namespace/radio gaps, and connection survival during a kill or transition.
- **Failure behavior:** Unknown attribution denies the action; missing grants launch Offline; Tor never falls back; transitions quarantine/tear down/restart; failed writes/enforcement deny affected connectivity. Emergency denial does not wait for signing/history availability. Restore removes only the global overlay under current authority.
- **Data/credentials:** Display public `key_id` only; keys remain in the vault. Use disposable test identities/profiles and avoid retaining private preview pixels, secrets, or sensitive rationale in artifacts. State threat-model limits and resource-specific revocation limits honestly.
- **Security review required:** YES. Input attribution, alias/profile isolation, privileged configuration, global network denial and authoritative UI status affect security boundaries. The author cannot independently approve their own work.
